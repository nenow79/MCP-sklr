## Zaakceptowany zakres paczki

Cel: sprawdzalny fundament rozliczania delegacji bez zmiany działających zgód i bez udostępnienia autopilota. Pełne reguły operacji i ich dopasowanie są paczką A2b2; A2b1 waliduje wyłącznie tożsamość i parametry budżetu. Licznik nie dowodzi dostępu do pliku ani prawa do uruchomienia narzędzia.

Pliki: nowy pakiet autopilot/ z pustym __init__.py, models.py i budget.py; tests/test_autopilot_models.py oraz tests/test_autopilot_budget.py. Bez zmian main.py, panelu, TaskManager, istniejących timeoutów, konfiguracji, zależności i lokalnych baz. Import pakietu niczego nie uruchamia, nie otwiera plików ani połączeń.

- models.py: niemutowalne modele powiązania (contract_id/session_id jako 32 małe znaki hex, dodatnie contract_revision i run_revision, odcisk zatwierdzonych reguł jako 64 małe znaki hex) oraz limitów (duration_s domyślnie 1800, maksimum 7200; max_operations domyślnie 100, maksimum 500; max_running=1). Zamknięta walidacja typów, bez bool jako liczby, zer, wartości ujemnych, NaN/inf i nieznanych pól. Rewizja przebiegu oznacza powiązanie nadane przez serwer przy zatwierdzeniu planu, nie session_id od modelu. Timeout zadania nie jest wspólnym polem tego budżetu — należy do profilu wykonawcy w następnej paczce.
- budget.py: jedna instancja RAM na konkretne powiązanie; wstrzyknięty monotoniczny zegar i jawny moment zatwierdzenia. Po utworzeniu prepared blokuje przyjęcia. Wewnętrzne metody activate/suspend/revoke oraz snapshot/reserve/start/finish/release nie są narzędziami MCP ani API panelu. Aktywacja po zawieszeniu wymaga jawnego wywołania integracji i zachowuje oryginalny deadline/zużycie; revoke/expired/exhausted nie są odwracane metodą activate. Nowy kontrakt wymaga nowej instancji.
- Rezerwacja ma nieprzezroczysty token przypięty do tej instancji; start atomowo zużywa ją raz i zwiększa liczbę rozpoczętych operacji. finish zwalnia współbieżność bez zwrotu zużytej próby. release zwalnia wyłącznie nierozpoczętą rezerwację. Brak/obcy/zużyty token i niewłaściwe powiązanie nie zmieniają liczników ani nie otwierają bramki.
- Inwariant used + reserved <= max_operations i running <= 1 pod RLock; synchronizacja wyścigu start/revoke/expiry. Chwilowo zajęta współbieżność zwraca busy bez utraty rezerwacji i bez fałszywego stanu exhausted. Pełna pula rezerwacji blokuje nowe rezerwacje, ale sama nie wyczerpuje trwale budżetu, bo może zostać zwolniona przed startem. Zużycie ostatniej operacji zamyka następne przyjęcia; rozpoczętą można domknąć.
- Deadline nie przesuwa się przez snapshot, pauzę lub reaktywację. Wygaśnięcie sprawdzane przy snapshot/próbie przyjęcia; działanie przyjęte wcześniej można finish także po revoke/expiry. Wątek nadzorczy i propagacja pauzy do sesji będą w A2b3; sam fundament nie obiecuje wykrycia upływu czasu bez wywołania. Zegar cofnięty/niefinitywny lub niespójność wewnętrzna blokują kolejne przyjęcia stałym recovery_required, bez ujawniania danych wejściowych.
- Snapshot i błędy zawierają tylko bezpieczne kody, powiązanie i agregaty, bez treści/argumentów/logów. Brak SQLite i dziennika oznacza brak uprawnienia do podłączenia do produkcyjnego dispatch — trwały ślad przed skutkiem jest warunkiem A2b3.
- Testy zachowania: błędne parametry/typy, prepared bez przyjęć, aktywacja, ostatnia jednostka, zwolnienie i ponowna rezerwacja, błędne/obce/powtórzone tokeny, busy bez podwójnego naliczenia, pauza bez resetu/deadline, cofnięcie/expiry z trwającą operacją, granica czasu i uszkodzony zegar, równoległy start/revoke oraz walka o ostatnią jednostkę. Zegar kontrolowany i bariery, bez długich sleep, sieci i procesów.
