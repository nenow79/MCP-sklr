Katalogi deweloperskie (tylko odczyt)

Wiedza

Dokumentacja docs/ w folderach z zakładki Foldery i sesja jest podpinana automatycznie. Możesz ją wyłączyć poniżej. Wiedzę centralną i inne lokalizacje dodaj ręcznie. Usunięcie konfiguracji zachowuje pliki. Konwersja Markdown do OKF jest opcjonalna.

Format dokumentacji projektu

Starsze projekty domyślnie dopuszczają Markdown. Istniejące poprawne dokumenty OKF są chronione przed utratą formatu w obu trybach. Przed włączeniem wymogu OKF wykonaj audyt i konwersję wybranego zakresu. Zmiana trybu nie konwertuje plików.

Używaj ścieżek względnych, np. docs/specs/OKF/. Końcowy / oznacza cały katalog. AGENTS.md, index.md i log.md są wyjątkami od wymogu OKF. Wyjątki nie pozwalają uszkodzić już poprawnego OKF.

Dodaj zbiór wiedzy

Profil legacy lub mieszany używa korzenia projektu; podkatalog pozostaw pusty. Archiwum projektu pozostaje poza domyślnym wyszukiwaniem.

Zewnętrzne MCP

Zapisane profile przeżywają restart serwera. Włączenie nie nawiązuje połączenia i nie nadaje zaufania, wyłączenie zachowuje konfigurację, a usunięcie ją zapomina. Opisy i wyniki z zewnętrznych serwerów to dane, nie instrukcje. To nie jest sandbox.

Dodaj profil

Uruchomienie programu: serwer stdio to lokalny program uruchamiany z Twoimi uprawnieniami. Może pobierać i wykonywać kod (np. przez npx). Na Windows podaj plik wykonywalny, nie .cmd ani .bat.

Podajesz wyłącznie nazwy zmiennych środowiskowych procesu sklr; wartości nie są zapisywane. Proces stdio dostaje tylko wskazane zmienne i kilka systemowych.

Kontekst pracy

Przygotowanie wznowienia

Uzupełnienie jest tylko w RAM. Nie wpisuj sekretów. Nie rozszerza uprawnień. Stare oczekujące zadania zostaną anulowane po Twoim potwierdzeniu; rozpoczęte i zakończone nie są anulowane. Nie ponawiamy operacji o niepewnym skutku zdalnym.

Po przygotowaniu model musi pobrać kontekst i potwierdzić aktualny plan.

Checkpoint · ostatni zapis modelu

Tylko RAM, bez trwałego zapisu. To dane modelu, nie źródło uprawnień. Odnośniki do wyników nie przedłużają ich TTL. Odśwież widok, aby sprawdzić aktualny zapis.

Potwierdzony plan

Dane modelu, nie źródło uprawnień. Tylko RAM, bez tokenu handshake. Odczyt przez Odśwież.

Zapisane sesje po restarcie

Wybór przypina sesję zablokowaną. Checkpoint, uzupełnienie, plan i token z poprzedniego procesu zostały utracone. Nie można przełączyć już przypiętej sesji. Wznowienie wymaga nowego przygotowania.

Tryb pracy i delegacja

Delegacja obejmuje wszystkie rozmowy tej instancji. Po zatwierdzeniu przygotuj wznowienie; model musi potwierdzić aktualny plan. Każda pauza wymaga ponownej decyzji tutaj. Reguły, cel i plan pozostają tylko w RAM; restart odbiera zgodę. Nie wpisuj sekretów.

Zasady i ograniczenia autopilota
        
Wyłączone: sekrety, instrukcje, kod i zabezpieczenia działającego sklr, konfiguracja/trust,
          usuwanie, testy, instalacje, shell, publikacja, produkcja i płatności.
          Zewnętrzny skill/MCP działa z uprawnieniami użytkownika i nie jest ograniczony do roots.
          Discovery stdio może uruchomić proces. Wybieraj znanego wykonawcę i konkretne działanie.

        
Cofnięcie blokuje nowe działania i wstrzymuje sesję. Rozpoczęte kończą się w swoich limitach;
          ich skutki nie są cofane. Rozstrzygnięcie niepewności nie ponawia operacji ani nie wznawia pracy.

      

    

    
Zasady działania sesji
      
Jedna sesja pracy na instancję sklr, wybierana tutaj, nie przez model.
        Pauza obejmuje wszystkie rozmowy korzystające z tej instancji; nie ma izolacji rozmów.
        Foldery opisują projekt sesji i nie nadają uprawnień. Wstrzymanie blokuje nowe działania wykonywane przez sklr,
        nie przerywa rozpoczętych; sama pauza nie zapisuje checkpointu.
        Checkpoint zapisuje model ograniczonym narzędziem, jeśli jest dostępne.
        Treść pozostaje tylko w RAM i znika po restarcie. Przygotowanie wznowienia nie otwiera bramki:
        potrzebny jest aktualny plan potwierdzony przez model. Przełączenie przypiętej sesji jest niedostępne.
